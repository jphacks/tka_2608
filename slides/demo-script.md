# ToDo〆～る 90秒発表台本

更新日: 2026-10-18。出典は別チャット「審査基準に沿ってドラフトを変更」でのユーザーの実演予定と、その後に作成した「時間・画面操作・セリフ」の表。全編実機を使う想定の台本です。実施・通し計測・提出が完了したという記録ではありません。

〇は説明役、▲はスマホ操作・寸劇役。20〜78秒の約58秒をデモに使い、85秒の合図の後に「あと1分だけ」で締める構成です。

| 時間 | 画面・操作 | セリフ |
| --- | --- | --- |
| 0〜7秒：導入 | ▲がInstagramを開き、5秒後に本体の制限画面へ進む | 〇「ちょっと、今は発表の時間ですよ！」／▲「あと1分だけ！」 |
| 7〜20秒：製品紹介 | 制限画面を見せたまま説明する | 〇「『あと1分だけ』のつもりが、気づけばやることを後回しに。そんな経験から生まれたのが、ToDo〆～るです。SNSを開きたくなった瞬間に、アリと相談して、今の行動を選び直せます。」 |
| 20〜35秒：アリに相談 | ToDo〆～るを開き、「あと1分だけInstagramを見たいです」と送信。「JPhacksの発表」が提案されたら選ぶ | 〇「上限に達した場面から、ここではアリに相談してみます。普段のリマインダーとつながっているので、今やるべきことを踏まえて返答してくれます。」 |
| 35〜42秒：取り組み開始 | 「JPhacksの発表」を選び、取り組みを開始する | 〇「今やることは、『JPhacksの発表』。」／▲「……そうだ、発表しよう！」 |
| 42〜66秒：発表する | 取り組み中の画面を映しながら、実際に製品説明をする | 〇「ToDo〆～るは、やることがあるのについSNSやゲームを開いてしまう人のためのアプリです。いつものリマインダーとアリへの相談をつなぎ、タスクを入力し直す手間を減らしました。利用の提案は、アプリ側でも時間や回数を検査します。アリとキリギリスと一緒に、納得して行動を選べる体験を目指しています。」 |
| 66〜78秒：完了・利用可能の表示 | 取り組みを終了し、「JPhacksの発表」を完了にする。Instagramが利用可能になったことをアプリ内の表示で見せる | ▲「発表、できました！」／〇「タスクを完了すると、Instagramに使える時間が追加されます。画面でも、利用できる状態になったことを確認できます。」 |
| 78〜85秒：まとめ | 操作を終えて、顔を上げる | 〇「スマホを開く瞬間を、やることへの一歩に。チーム『あと1分だけ』です！」 |
| 85〜90秒：オチ | 運営の合図を受け、一礼して終了する | 運営「お時間です」／▲「あと1分だけ、時間ください！」 |

## 実演前に確認すること

- 最初のスマホ操作から計測するか、85秒で合図をもらえるかを運営に確認する。
- 実演端末のリマインダーに「JPhacksの発表」を未完了で登録し、相談文と画面共有を準備する。
- Instagramから5秒後に本体の制限画面へ進む経路は、[PersonalDemoのショートカット設定](../docs/SHORTCUTS_DEMO.md) を使う想定。OSが実使用時間を測ってShieldを出す通常版の動作とは分けて説明する。
- AIの返答は固定しない。想定の提案が出ない場合や応答が長い場合の進め方を練習し、操作とセリフを通して90秒に収まるか計測する。
- 実演でClaude API・端末内AI・固定応答のどれを使ったか記録する。元の台本の「端末内AIのみ」という技術説明は、現行mainの複数の経路に合わせて一般的な「アリへの相談」にした。
- PersonalDemoは通常版の実アプリ制限・使用時間計測・時間経過による再制限を実証するものではない。解除の実演はユーザー指定どおりアプリ内の表示で示す。

別チャットにはユーザーの「実機で動くが所要時間は未計測」という報告があります。端末・OS・Scheme・AIの種別・検証commitは不明です。この台本の収録を、現行mainでの実機検証・リハーサル完了とは扱いません。
