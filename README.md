## 審査基準に対応する3つの強み

[公式の審査基準](https://jphacks-info.notion.site/f469bc2d28a7834bacf68176ac270d9a)の3項目に沿って、本作品の強みをまとめます。

### 1. 問題着眼点・着想点

**「ついついスマホを開いてしまう」という行為を、プラスに変える着想。**

やることがあるのに、ついスマホでSNSを開いてしまい、やることが進まず、そんな自分に落ち込んでしまう。私たちは、この体験と「ついついスマホを開いてしまう」こと自体にあるネガティブなイメージに着目しました。スマホを開いたときに、本人のやることを踏まえたAIチューターのアドバイスを届け、やるべきことの遂行を後押しします。同じ「スマホを開く」というきっかけを、「やることが一つ進んだ」と感じられる前向きな体験につなげることが、私たちの着想です。

### 2. 実行・実現可能性

**いつものリマインダーと端末から始められる構成。**

対象は、課題や家事などのやることがあるのに、SNSやゲームを開いてしまう学生・社会人です。Apple標準リマインダーからやることを取得するため、タスクを別アプリへ入力し直す手間を抑えられます。相談には端末内AIを使い、記録も端末内で扱う構成にすることで、独自の推論サーバーを前提にせず、普段の生活に取り入れやすい形を目指しています。

### 3. 完成度・動作性

**取り組みと相談の2ルートを、SNS時間の獲得・利用枠の発行まで実装。**

「やることを選ぶ → 取り組む → ふりかえる → SNS時間を獲得する」と、「アリに相談する → 提案を検査する → 短時間の利用枠を発行する」の2ルートを実装しました。[解除ポリシー](todomeru_ios/todomeru_ios/Core/UnlockPolicy.swift)によるAI提案の再検査と、[SNS時間の台帳](todomeru_ios/todomeru_ios/Core/AppStore.swift)による二重付与・二重交換の防止まで、会話と利用制御をつなぐ処理を設けています。

PersonalDemo版はアプリ内の疑似SNSで利用・終了の流れを再現する構成です。実SNSの制限・バックグラウンドでの再制限は通常版にコードがあり、実機での動作は未検証です。確認済みのビルド・テストと、追加検証が必要な範囲は、後述の「動作デモ・実装状況」に記載しています。

## 製品概要

### 背景（製品開発のきっかけ、課題等）

#### 開発のきっかけ：「あと一分だけ」で、やることが進まない

少しだけSNSを見るつもりが、そのままやることを後回しにしてしまう。やることが進まないまま時間が過ぎ、そんな自分に落ち込んでしまう。私たち自身のこの困りごとが、開発の出発点です。レポートや家事の前にSNS・ゲームを開く場面などを想定しています。

#### 課題：「ついついスマホを開いてしまう」がネガティブに受け止められる

私たちが解決したいのは、**やることがあるのにSNSを開き、やることが進まず、そんな自分に落ち込んでしまうこと**です。

「ついついスマホを開いてしまう」こと自体に、社会的にも個人的にもネガティブなイメージがある、という問題意識を持っています。スマホを開いた後の後悔や落ち込みにつながる体験を、やることが進む前向きな体験へ変えたいと考えました。

#### 想定ユーザーと利用場面

対象は、**本当はやらなければいけないことがあるのに、ついSNSやゲームを開いてしまう人**です。学生に限らず、一人暮らしの社会人など、生活のやることを後回しにしがちな人も想定しています。

| 利用場面の例 | 困りごと | ToDo〆～るで目指す体験 |
| --- | --- | --- |
| 課題の途中でSNSを開く学生 | 書き出しで手が止まり、SNSを見続けてしまう | リマインダーにある課題を確認し、「まずここだけ」と取り組む内容を選ぶ |
| 家事の前にゲームを開く社会人 | 息抜きを始めると、洗濯や片付けに戻れない | 家事を一つ選び、取り組んだ時間や完了をふりかえる |
| やることの途中で連絡を確認したい人 | 制限中でも、今確認する必要がある | 利用目的と、その後に取り組むことを相談し、ルールの範囲で短時間利用する |

これらは想定する利用場面です。利用者調査や効果測定の結果を示すものではありません。

#### 解決策：「ついついスマホを開いてしまう」をポジティブに

**スマホを開くきっかけを、やるべきことが進むプラスのきっかけに変えることを目指します。**

ついついスマホを開いてしまったときに、AIチューター「アリ」が、普段のリマインダーにある本人のやることを踏まえてアドバイスします。対話を通じて具体的に取り組む内容を示し、ユーザーがやるべきことを遂行できるよう後押しします。

同じ「スマホを開く」という行為でも、「SNSに時間を使ってしまった」という後悔から、「やることを一つ進められた」という前向きな実感につなげたいと考えています。必要なSNS利用について理由を相談できることも、この体験を支える機能です。

### 製品説明（具体的な製品の説明）

ToDo〆～るは、**Apple標準リマインダー・Screen Time・端末内AIを組み合わせ、「ついついスマホを開いてしまう」ことを、やるべきことの遂行につなげるアプリ**です。

基本の利用フローは次のとおりです。

1. 連携するリマインダーのリストと、制限するアプリ、アプリごとの1日の上限を選ぶ。
2. SNSが上限に達したら、ToDo〆～る本体で「やることに取り組む」「アリに相談する」の行動を選ぶ。
3. やることに取り組んだ場合は、時間を記録してふりかえり、獲得したSNS時間を利用したいアプリへ追加する。
4. アリに相談した場合は、利用目的とやることを踏まえて対話する。短時間利用の提案をアプリ側が検査し、条件を満たした場合に利用枠を発行する。
5. 利用枠を使い切ったら再び制限し、やることを選び直す。

通常版には、iOSの制限画面を適用する処理を実装しています。アリとの対話とやることの選択はToDo〆～る本体で行います。現在のPersonalDemo版は、アプリ内の疑似SNSでこの流れを再現する構成です。実装と動作確認の範囲は、後述の「動作デモ・実装状況」に記載しています。

### 特長

#### 1. 「ついつい開く」を、やることが進むきっかけに

スマホを開いたときに、アリが本人のやることを思い出させ、具体的な取り組みを後押しします。Apple標準リマインダーの選択したリストから、やること・期限・完了状態を取得するため、新しいToDoアプリへの入力し直しを減らし、普段の課題や家事をそのまま取り組みの対象にできます。

取り組み後は「完了にする」「まだ続ける」を選んでふりかえります。現在の実装では、**25分の取り組みごとにSNS時間5分、やること1件の完了で1分**を獲得できます。完了報酬は、リマインダーの更新に成功した後に付与します。

#### 2. 「今使いたい理由」を相談できる

「何となく見たい」と「集合場所の連絡を確認したい」では、必要な行動が異なります。アリは、本人のやることと会話をもとに、事情の確認、やることへの小さな着手、短時間のSNS利用を提案します。

例えば「連絡を確認したらレポートに戻る」と伝えた場合に、必要性と利用後の行動を確認する、といった対話を想定しています。これは説明用の例であり、毎回同じ応答や利用許可を保証するものではありません。

AIが利用を提案した後も、納得度・利用秒数・相談回数などをアプリ側が再検査します。現在のルールは**相談が1日3回まで、1回の相談でユーザーの発言は最大5通、納得度70%以上で1〜5分の利用を提案可能**です。1日の区切りは、端末の現地時刻の午前4時から翌午前4時です。

#### 3. アリとキリギリスと一緒に、変化を見つける

童話「アリとキリギリス」をモチーフに、アリを相談相手、キリギリスをユーザーの分身として描きました。会話の納得度や取り組みの進み具合を表情で伝え、数値だけでは感じにくい変化を見えるようにしています。

会話ではユーザーを責めず、短く具体的な次の行動を提案することを重視しました。相談の途中からでも、やることを選んで取り組みに進める導線を用意しています。

### 既存の方法に対して重視した違い

| 課題へのアプローチ | ToDo〆～るで結びつけたこと |
| --- | --- |

比較の軸は、**本人のやること・利用したい事情・利用ルールを一つの体験にまとめたこと**です。競合サービスの網羅的な調査や、利用者による優位性の検証は今後行います。

### 解決できること・目指す変化

- 「ついついスマホを開いてしまう」を、やることが進む前向きな体験につなげる。
- やることが進まない自分への落ち込みを、「一つ進められた」という実感へつなげることを目指す。
- SNSに流れそうなときに、今取り組めるやることを思い出す。
- 大きなやることにも、まず小さな一歩から着手する。
- 必要なSNS利用について理由と戻る先を考え、区切りをつける。
- 取り組んだ時間や完了をふりかえり、次の行動につなげる。

こうした体験を支える機能を実装しています。やることの遂行や利用後の気持ちの変化、SNS時間の削減などの効果は今後の検証対象です。

### 注力したこと（こだわり等）

## 動作デモ・実装状況

### デモで示す2つのルート

「レポートが残っているのにSNSを開きたい」という同じ場面から、次の2つを見せる構成です。以下は実装をもとにした確認・撮影手順であり、撮影済み・実機検証済みという意味ではありません。

| ルート | 操作の流れ | 確認すること |
| --- | --- | --- |
| やることに取り組む | 本体の制限画面 → やることを選択 → 取り組み → ふりかえり → SNS時間を追加 | 本人のやることから着手し、取り組み時間・完了とSNS時間がつながること |
| アリに相談する | 本体の制限画面 → 利用理由を相談 → 提案を検査 → 短時間利用 → 利用終了・再制限 | 理由に応じた対話と、ルール内の利用枠・終了後の状態がつながること |

PersonalDemoでは「SNSの使用時間」で「上限まで進める」→「開く（デモ）」を選び、本体の制限画面に進みます。そこから上記の2ルートを操作し、疑似SNSで利用枠の消費と終了後の画面を確認する手順を用意しています。デモの倍速や取り組み時間の短縮を使う場合は、動画内でも分かるようにします。端末内AIが利用できず「デモ用の固定応答」に切り替わった場合も、その表示を含めます。

### 開発環境・起動方法

- 対象：iPhone。プロジェクトの最低OS設定は **iOS 26.0**。
- 開発：Mac / Xcode。端末内AIの使用には、実行端末でFoundation Modelsが利用可能であることが必要です。
- Personal Teamでのデモ：Xcodeで [todomeru_ios.xcodeproj](todomeru_ios/todomeru_ios.xcodeproj) を開き、[ローカル署名設定](todomeru_ios/Config/README.md)を行って、Scheme `todomeru_ios_PersonalDemo` を選びます。
- 実SNS制限を検証する通常版：Scheme `todomeru_ios` を使用します。Family Controls / App Groupsに対応するTeam・プロファイル・App Groupの設定が必要です。詳細は同じ署名設定ガイドに記載しています。

既存の検証記録で成功した、PersonalDemo版のDebugビルドコマンドです。リポジトリのルートで実行します。

```sh
xcodebuild -project todomeru_ios/todomeru_ios.xcodeproj -scheme todomeru_ios_PersonalDemo -configuration Debug -destination 'generic/platform=iOS' -quiet build
```

ビルド成功と実機での動作確認は分けて記載しています。端末・OS・AIの使用有無を含む動作動画の追加が、提出前の残作業です。

- iPhone（iOS 26以上）

### 独自技術

#### ハッカソンで開発した独自機能・技術

- AIとの相談の設計：端末内AIには、返答・納得度・次の行動を決まった型で出させる。やることの名前や会話はデータとして扱い、会話から判定を書き換えられるのを防ぐ。AIが「許可」を出しても、アプリのルールで再検査してから制限を解く
- アプリを閉じていても効く制限：上限への到達や一時利用の終了をスクリーンタイムの拡張機能で検知し、アプリが裏にいても制限をかけ直す
- 使用時間の扱い：SNSの使用時間はスクリーンタイムの拡張機能の中だけで扱い、アプリ本体には渡さない
- SNS時間の台帳：獲得と利用を取引として記録し、同じ報酬の二重付与を防ぐ
- 端末内AIがなくても動く相談：端末内AIを使えないiPhoneでは、キーワードから納得度を出す簡易応答で相談を続ける
