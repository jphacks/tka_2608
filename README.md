# ToDo〆～る - 「あと1分だけ」にトドメを

**「ついついスマホを開いてしまう」を、やることが進む前向きなきっかけに。**

ToDo〆～るは、ついスマホでSNSを開いてしまう瞬間に、AIチューター「アリ」がアドバイスし、やるべきことの遂行を後押しするiPhoneアプリです。スマホを開いたことが、やることが一つ進むプラスのきっかけになる体験を目指しています。

## 審査基準に対応する3つの強み

[公式の審査基準](https://jphacks-info.notion.site/f469bc2d28a7834bacf68176ac270d9a)の3項目に沿って、本作品の強みをまとめます。

### 1. 問題着眼点・着想点

**「ついついスマホを開いてしまう」という行為を、プラスに変える着想。**

やることがあるのに、ついスマホでSNSを開いてしまい、やることが進まず、そんな自分に落ち込んでしまう。私たちは、この体験と「ついついスマホを開いてしまう」こと自体にあるネガティブなイメージに着目しました。スマホを開いたときに、本人のやることを踏まえたAIチューターのアドバイスを届け、やるべきことの遂行を後押しします。同じ「スマホを開く」というきっかけを、「やることが一つ進んだ」と感じられる前向きな体験につなげることが、私たちの着想です。

### 2. 実行・実現可能性

**いつものリマインダーと端末から始められる構成。**

対象は、課題や家事などのやることがあるのに、SNSやゲームを開いてしまう学生・社会人です。Apple標準リマインダーからやることを取得するため、タスクを別アプリへ入力し直す手間を抑えられます。相談はClaude API、端末内AI、固定応答を設定と利用可否に応じて使い分け、取り組みの記録は端末内に保存します。Claude APIを使う場合は、やることの名前・期限と会話を外部へ送信します。

### 3. 完成度・動作性

**取り組みと相談の2ルートを、SNS時間の獲得・利用枠の発行まで実装。**

「やることを選ぶ → 取り組む → ふりかえる → SNS時間を獲得する」と、「アリに相談する → 提案を検査する → 短時間の利用枠を発行する」の2ルートを実装しました。[解除ポリシー](todomeru_ios/todomeru_ios/Core/UnlockPolicy.swift)によるAI提案の再検査と、[SNS時間の台帳](todomeru_ios/todomeru_ios/Core/AppStore.swift)による二重付与・二重適用の防止まで、会話と利用制御をつなぐ処理を設けています。

PersonalDemo版には、Instagramからショートカット経由で本体へ進み、相談・取り組み・完了後の利用可能表示を見せる導線と、アプリ内の疑似SNSがあります。通常版にはScreen Timeによる実アプリの制限・再制限を実装していますが、その実機検証は別途必要です。既存の統合記録では単体テスト85件とPersonalDemoのSimulatorビルドが成功しています。ユーザーの実機動作報告と、追加検証が必要な範囲は、後述の「動作デモ・実装状況」に分けて記載しています。

## 製品概要

### 背景（製品開発のきっかけ、課題等）

#### 開発のきっかけ：「あと一分だけ」で、やることが進まない

少しだけSNSを見るつもりが、そのままやることを後回しにしてしまう。やることが進まないまま時間が過ぎ、そんな自分に落ち込んでしまう。私たち自身のこの困りごとが、開発の出発点です。レポートや家事の前にSNS・ゲームを開く場面などを想定しています。

#### 課題：「ついついスマホを開いてしまう」がネガティブに受け止められる

私たちが解決したいのは、**やることがあるのにSNSを開き、やることが進まず、そんな自分に落ち込んでしまうこと**です。

「ついついスマホを開いてしまう」こと自体に、社会的にも個人的にもネガティブなイメージがある、という問題意識を持っています。スマホを開いた後の後悔や落ち込みにつながる体験を、やることが進む前向きな体験へ変えたいと考えました。

#### 想定ユーザーと利用場面

対象は、**本当はやらなければいけないことがあるのに、ついSNSやゲームを開いてしまう人**です。学生に限らず、一人暮らしの社会人など、生活のやることを後回しにしがちな人も想定しています。

| 利用場面の例 | 困りごと | ToDo〆～るで目指す体験 |
| --- | --- | --- |
| 課題の途中でSNSを開く学生 | 書き出しで手が止まり、SNSを見続けてしまう | リマインダーにある課題を確認し、「まずここだけ」と取り組む内容を選ぶ |
| 家事の前にゲームを開く社会人 | 息抜きを始めると、洗濯や片付けに戻れない | 家事を一つ選び、取り組んだ時間や完了をふりかえる |
| やることの途中で連絡を確認したい人 | 制限中でも、今確認する必要がある | 利用目的と、その後に取り組むことを相談し、ルールの範囲で短時間利用する |

これらは想定する利用場面です。利用者調査や効果測定の結果を示すものではありません。

#### 解決策：「ついついスマホを開いてしまう」をポジティブに

**スマホを開くきっかけを、やるべきことが進むプラスのきっかけに変えることを目指します。**

ついついスマホを開いてしまったときに、AIチューター「アリ」が、普段のリマインダーにある本人のやることを踏まえてアドバイスします。対話を通じて具体的に取り組む内容を示し、ユーザーがやるべきことを遂行できるよう後押しします。

同じ「スマホを開く」という行為でも、「SNSに時間を使ってしまった」という後悔から、「やることを一つ進められた」という前向きな実感につなげたいと考えています。必要なSNS利用について理由を相談できることも、この体験を支える機能です。

### 製品説明（具体的な製品の説明）

ToDo〆～るは、**Apple標準リマインダー・アプリの利用制限・アリとの相談を組み合わせ、「ついついスマホを開いてしまう」ことを、やるべきことの遂行につなげるiPhoneアプリ**です。通常版の利用制限にはScreen Timeを使い、相談は設定に応じてClaude APIまたは端末内AIで行います。

基本の利用フローは次のとおりです。

1. 連携するリマインダーのリストと、制限するアプリ、アプリごとの1日の上限を選ぶ。
2. SNSが上限に達したら、ToDo〆～る本体で「やることに取り組む」「アリに相談する」の行動を選ぶ。
3. やることに取り組んだ場合は、時間を記録してふりかえり、獲得したSNS時間を利用したいアプリへ追加する。
4. アリに相談した場合は、利用目的とやることを踏まえて対話する。短時間利用の提案をアプリ側が検査し、条件を満たした場合に利用枠を発行する。
5. 通常版では利用枠を使い切ったら再び制限し、やることを選び直す。

通常版には、iOSの制限画面を適用する処理を実装しています。アリとの対話とやることの選択はToDo〆～る本体で行います。PersonalDemo版のInstagram導線は、iPhoneのショートカットで本体を開く構成で、実アプリの使用時間の計測・時間経過による再制限は行いません。実装と動作確認の範囲は、後述の「動作デモ・実装状況」に記載しています。

### 特長

#### 1. 「ついつい開く」を、やることが進むきっかけに

スマホを開いたときに、アリが本人のやることを思い出させ、具体的な取り組みを後押しします。Apple標準リマインダーの選択したリストから、やること・期限・完了状態を取得するため、新しいToDoアプリへの入力し直しを減らし、普段の課題や家事をそのまま取り組みの対象にできます。

取り組み後は「完了にする」「まだ続ける」を選んでふりかえります。現在の実装では、**25分の取り組みごとにSNS時間5分、やること1件の完了で1分**を獲得できます。完了報酬は、リマインダーの更新に成功した後に付与します。

獲得した時間は、その取り組みの分をふりかえりの最後に選んだアプリへ追加します。別の取り組みの分を貯める残高の仕組みは設けていません。

#### 2. 「今使いたい理由」を相談できる

「何となく見たい」と「集合場所の連絡を確認したい」では、必要な行動が異なります。アリは、本人のやることと会話をもとに、事情の確認、やることへの小さな着手、短時間のSNS利用を提案します。

例えば「連絡を確認したらレポートに戻る」と伝えた場合に、必要性と利用後の行動を確認する、といった対話を想定しています。これは説明用の例であり、毎回同じ応答や利用許可を保証するものではありません。

やることを選んだ後は、進み具合を1問だけ聞き、5分以内にできる最初の一歩を1つ提案します。答えずに取り組みを始めることもできます。やることの名前・期限と本人の答えを使い、文書の中身やリマインダーのメモを読める前提にはしていません。

AIが利用を提案した後も、納得度・利用秒数・相談回数などをアプリ側が再検査します。通常版のルールは**相談が1日3回まで、1回の相談でユーザーの発言は最大5通、納得度70%以上で1〜5分の利用を提案可能**です。PersonalDemoでは相談の1日の回数制限を外しています。1日の区切りは、端末の現地時刻の午前4時から翌午前4時です。

#### 3. アリとキリギリスと一緒に、変化を見つける

童話「アリとキリギリス」をモチーフに、アリを相談相手、キリギリスをユーザーの分身として描きました。会話の納得度や取り組みの進み具合を表情で伝え、数値だけでは感じにくい変化を見えるようにしています。

会話ではユーザーを責めず、短く具体的な次の行動を提案することを重視しました。相談の途中からでも、やることを選んで取り組みに進める導線を用意しています。

### 既存の方法に対して重視した違い

| 課題へのアプローチ | ToDo〆～るで結びつけたこと |
| --- | --- |
| 利用時間の上限による制限 | 制限に加えて、本人のやることを確認し、着手する内容を選ぶ導線を用意 |
| ユーザーから始めるAI相談 | SNSを使いたい場面から相談へ進み、利用理由と本人のやることを一緒に扱う |
| やることの一覧・通知 | 取り組み・ふりかえりと、SNS時間の獲得・利用を一連の操作につなぐ |

比較の軸は、**本人のやること・利用したい事情・利用ルールを一つの体験にまとめたこと**です。競合サービスの網羅的な調査や、利用者による優位性の検証は今後行います。

### 解決できること・目指す変化

- 「ついついスマホを開いてしまう」を、やることが進む前向きな体験につなげる。
- やることが進まない自分への落ち込みを、「一つ進められた」という実感へつなげることを目指す。
- SNSに流れそうなときに、今取り組めるやることを思い出す。
- 大きなやることにも、まず小さな一歩から着手する。
- 必要なSNS利用について理由と戻る先を考え、区切りをつける。
- 取り組んだ時間や完了をふりかえり、次の行動につなげる。

こうした体験を支える機能を実装しています。やることの遂行や利用後の気持ちの変化、SNS時間の削減などの効果は今後の検証対象です。

### 注力したこと（こだわり等）

- **相談から行動までつなぐUI。** 本体の制限画面から、やることへの取り組みと相談の2つを選べるようにしました。相談中に気が変わっても、取り組みへ進めます。[UI・対話設計](docs/UI_UX.md)をもとに実装しています。
- **対話の待ち時間への配慮。** 返答の逐次表示と、端末内AIを使う場合のモデルの事前読み込みを実装しました。Claude API・端末内AIで生成に失敗した場合は固定応答へ切り替えます。
- **会話の提案と利用制御をつなぐ処理。** AIの出力をアプリ側で検査し、利用枠の発行から終了までを状態として管理します。獲得したSNS時間は台帳に記録し、同じ操作による二重付与・二重適用を防ぐ処理を設けました。

### 今後の展望

まず、対応する署名環境と実機で、リマインダー取得からAI対話、実SNSの一時利用、バックグラウンドでの再制限までを通して検証します。そのうえで想定ユーザーに使ってもらい、やることを始められた割合、利用後にやることへ戻れたか、提案への納得感を確かめ、対話とルールを改善します。

タスクの入力し直しや推論用サーバーの準備を増やさず、普段の端末とリマインダーから使い始められる構成を目指しています。対象端末・配布条件を確認しながら利用できる範囲を広げ、将来はAndroidへの展開も検討します。

### 開発環境・起動方法

- 対象：iPhone。プロジェクトの最低OS設定は **iOS 26.0**。
- 開発：Mac / Xcode。端末内AIの使用には、実行端末でFoundation Modelsが利用可能であることが必要です。
- Personal Teamでのデモ：Xcodeで [todomeru_ios.xcodeproj](todomeru_ios/todomeru_ios.xcodeproj) を開き、[ローカル署名設定](todomeru_ios/Config/README.md)を行って、Scheme `todomeru_ios_PersonalDemo` を選びます。
- 実SNS制限を検証する通常版：Scheme `todomeru_ios` を使用します。Family Controls / App Groupsに対応するTeam・プロファイル・App Groupの設定が必要です。詳細は同じ署名設定ガイドに記載しています。
- Claude APIを使う場合：同じ [設定ガイド](todomeru_ios/Config/README.md) に従い、Git除外対象の `ClaudeAPI.local.xcconfig` または実行環境の `ANTHROPIC_API_KEY` にキーを設定します。設定した場合は通信が必要で、やることの名前・期限と会話をAnthropicへ送信します。現在のキー組込み方式はハッカソンのデモ用で、配布時の方式は別途整備が必要です。

既存の検証記録で成功した、PersonalDemo版のDebugビルドコマンドです。リポジトリのルートで実行します。

```sh
xcodebuild -project todomeru_ios/todomeru_ios.xcodeproj -scheme todomeru_ios_PersonalDemo -configuration Debug -destination 'generic/platform=iOS' -quiet build
```

ビルド成功と実機での動作確認は分けて記載しています。端末・OS・AIの使用有無を含む動作動画の追加が、提出前の残作業です。

## 開発技術

### 活用した技術

#### API・データ

- アプリのデータ：JSONファイルに保存
- やること：リマインダーと連携（EventKit）
- 相談と最初の一歩：Claude API（Anthropic Messages API）をキー設定時に使用。未設定時は端末内AI（Apple Foundation Models）、利用不可・生成失敗時は固定応答
- Claude API利用時：やることの名前・期限と会話を外部送信。API通信・利用料金が発生する
- 本体と拡張機能の間：通常版はApp Groupで制限の状態を共有。PersonalDemoはApp Groups entitlementを使わない

#### フレームワーク・ライブラリ・モジュール

- SwiftUI / Observation
- Foundation Models（端末内AI）
- Foundation / URLSession（Claude APIへのHTTP通信・ストリーミング）
- App Intents / ショートカット（PersonalDemoのInstagram導線）
- Screen Time API（FamilyControls / ManagedSettings / DeviceActivity）
- EventKit（リマインダー連携）
- Swift Charts（利用時間のグラフ）
- Swift Testing（テスト）

#### デバイス

- iPhone（iOS 26以上）

### 独自技術

#### ハッカソンで開発した独自機能・技術

- AIとの相談の設計：Claude APIと端末内AIで、返答・納得度・次の行動を決まった型で出させる。やることの名前や会話はデータとして扱う。AIが「許可」を出しても、アプリのルールで再検査する
- 取り組む最初の一歩：やることの進み具合を1問聞き、名前・期限と本人の答えから5分以内の一歩を提案する。リマインダーのメモや文書の中身を読む前提を置かない
- アプリを閉じていても効く制限：通常版では上限への到達や一時利用の終了をScreen Timeの拡張機能で検知し、バックグラウンドで再制限するコードを実装。実機での一連の動作は未検証
- 使用時間の扱い：SNSの使用時間はスクリーンタイムの拡張機能の中だけで扱い、アプリ本体には渡さない
- SNS時間の台帳：獲得記録と、選んだアプリへの追加を記録し、同じ報酬の二重付与・二重適用を防ぐ
- 相談の切り替え：Claude API、端末内AI、固定応答を設定と利用可否で使い分け、生成失敗時にも相談を継続する

#### 特に力を入れた部分
