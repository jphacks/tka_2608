## 「ToDo〆～る」について

ToDo〆～る は、Apple標準リマインダー・Screen Time・端末内AIを組み合わせ、「ついついスマホを開いてしまう」ことを、やるべきことの遂行につなげるアプリです。

<img width="1920" height="1080" alt="image" src="https://github.com/user-attachments/assets/5f20dfd1-434f-4d60-8bb0-49d9cb82f122" />

基本の利用フロー：

1. 連携するリマインダーのリストと、制限するアプリ、アプリごとの1日の上限を選ぶ。
2. SNSが上限に達したら、ToDo〆～る本体で「やることに取り組む」「アリに相談する」の行動を選ぶ。
3. やることに取り組んだ場合は、時間を記録してふりかえり、獲得したSNS時間を利用したいアプリへ追加する。
4. アリに相談した場合は、利用目的とやることを踏まえて対話する。短時間利用の提案をアプリ側が検査し、条件を満たした場合に利用枠を発行する。
5. 利用枠を使い切ったら再び制限し、やることを選び直す。

### ✨ 設計のこだわりポイント

#### 1. 「ついつい開く」を、やることが進むきっかけに

    スマホを開いたときに、アリが本人のやることを思い出させ、具体的な取り組みを後押しします。

    Apple標準リマインダーの選択したリストから、やること・期限・完了状態を取得する設計にしました。新しいToDoアプリへの入力し直しを減らし、普段の課題や家事をそのまま取り組みの対象にできます。

    取り組み後は「完了にする」「まだ続ける」を選んでふりかえります。現在の実装では、**25分の取り組みごとにSNS時間5分、やること1件の完了で1分**を獲得できます。完了報酬は、リマインダーの更新に成功した後に付与します。

#### 2. 「今使いたい理由」を相談できる

    「何となく見たい」と「集合場所の連絡を確認したい」では、必要な行動が異なります。

    アリは、本人のやることと会話をもとに、事情の確認、やることへの小さな着手、短時間のSNS利用を提案します。

    例えば「連絡を確認したらレポートに戻る」と伝えた場合に、必要性と利用後の行動を確認する、といった対話を想定しています。

    現在のルールは**相談が1日3回まで、1回の相談でユーザーの発言は最大5通、納得度70%以上で1〜5分の利用を提案可能**です。制限は、午前4時にリセットされます。

#### 3. アリとキリギリスと一緒に、変化を見つける

    童話「アリとキリギリス」をモチーフに、アリを相談相手、キリギリスをユーザーの分身として描きました。

    会話の納得度や取り組みの進み具合を表情で伝え、数値だけでは感じにくい変化を見えるようにしています。

    会話ではユーザーを責めず、短く具体的な次の行動を提案することを重視しました。相談の途中からでも、やることを選んで取り組みに進める導線を用意しています。

### 🐜 ToDo〆～るは、よくある利用制限アプリ・ToDoアプリではない！

| 課題へのアプローチ       | ToDo〆～るで結びつけたこと                                            |
| ------------------------ | --------------------------------------------------------------------- |
| 利用時間の上限による制限 | 制限に加えて、本人のやることを確認し、着手する内容を選ぶ導線を用意    |
| ユーザーから始めるAI相談 | SNSを使いたい場面から相談へ進み、利用理由と本人のやることを一緒に扱う |
| やることの一覧・通知     | 取り組み・ふりかえりと、SNS時間の獲得・利用を一連の操作につなぐ       |

- やることが進まない自分への落ち込みを、「一つ進められた」という実感へつなげることを目指す。

## 起動方法

- 開発（ビルド時）：Mac / Xcode

- テストデバイス：iPhone (iOS26.0以上)

1. 事前準備（言語・権限の設定）
   - 端末内AIを使用するため、テストデバイスでFoundation Modelsが利用可能であることが必要です。また、SiriとAppleIntelligenceの言語設定を統一してください。

   - iOSのスクリーンタイムと連携するため、Family Controls / App Groupsに対応するTeam・プロファイル・App Groupの設定が必要です。

2. アプリのビルド
   Xcodeで [todomeru_ios.xcodeproj](todomeru_ios/todomeru_ios.xcodeproj) を開き、[ローカル署名設定](todomeru_ios/Config/README.md)を行って、Scheme `todomeru_ios` を選びます。

   その後、リポジトリのルートで、以下のコマンドを実行してください。

   ```sh
   xcodebuild -project todomeru_ios/todomeru_ios.xcodeproj -scheme todomeru_ios -configuration Debug -destination 'generic/platform=iOS' -quiet build
   ```

## 技術スタック

#### API・データ

- 外部API・サーバーなし（データは端末内で完結）
- アプリのデータ：JSONファイルに保存
- やること：リマインダーと連携（EventKit）
- AIとの会話：端末内AI（Apple Foundation Models）。使えない端末ではキーワードによる簡易応答に切り替え
- 本体と拡張機能の間：App Group で制限の状態を共有

#### フレームワーク・ライブラリ・モジュール

- SwiftUI / Observation
- Foundation Models（端末内AI）
- Screen Time API（FamilyControls / ManagedSettings / DeviceActivity）
- EventKit（リマインダー連携）
- Swift Charts（利用時間のグラフ）
- Swift Testing（テスト）

### 独自技術

#### ハッカソンで開発した独自機能・技術

- AIとの相談の設計：端末内AIには、返答・納得度・次の行動を決まった型で出させる。やることの名前や会話はデータとして扱い、会話から判定を書き換えられるのを防ぐ。AIが「許可」を出しても、アプリのルールで再検査してから制限を解く
- アプリを閉じていても効く制限：上限への到達や一時利用の終了をスクリーンタイムの拡張機能で検知し、アプリが裏にいても制限をかけ直す
- 使用時間の扱い：SNSの使用時間はスクリーンタイムの拡張機能の中だけで扱い、アプリ本体には渡さない
- SNS時間の台帳：獲得と利用を取引として記録し、同じ報酬の二重付与を防ぐ
- 端末内AIがなくても動く相談：端末内AIを使えないiPhoneでは、キーワードから納得度を出す簡易応答で相談を続ける
