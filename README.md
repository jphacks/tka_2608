## 製品概要

### 背景（製品開発のきっかけ、課題等）

#### 開発のきっかけ

SNSをちょっと見るだけのつもりが、気づけば何時間もSNSを見ていて、やるべきことを後回しにしていた経験はありませんか？
そんな「あと一分だけ」をやめられない私達に向けてSNSを開いたときにAIを説得しないと開けないアプリを開発しました。

#### 課題：「スマホを開く」という行為がネガティブ

やることがあるのに、ついついスマホでSNSを開いてしまい、やることが進まず、そんな自分に落ち込んでしまった経験は誰にでもあるはずです。
現在、「ついついスマホを開いてしまう」こと自体が、社会的にも個人的にもネガティブなイメージがあります。

#### 解決策：「ついついスマホを開いてしまう」をポジティブに

「スマホを開く」というきっかけは同じだが、「SNSに使ってしまった」が、「やることが一個進んだ」に代わることで、スマホを開く行為自体のネガティブな印象をなくせる。
具体的には、ついついスマホを開いてしまったときに，AIを利用したチューター的存在がアドバイスをくれて，ユーザーがやるべきことを遂行できるようにする。

#### 既存の商品との差異

SNSを見ちゃう既存の制限アプリ -スクリーンタイム:自分で制限が解除できるor親の許可が必要（親に連絡がつかないと困る）-その他一度使ったら一定時間立つまであかない制限アプリ:本当に必要な時に困る

-AIはいつでも自分の好きな時間に動いて止めてくれる。

chatGPTなどの生成AIとの差異：
生成AIは、こちらからお願いしなければならないので、こちらが能動的に動く必要がある。
一方こちらは相手から提案してもらえるので、受動的に制限をしてもらえる。

### 製品説明（具体的な製品の説明）

**ToDoメ**は、Apple標準のリマインダー、スクリーンタイム、Apple intelligenceをつなぎ、ユーザーのタスクへの着手を後押しするiosアプリです。

普段使っているリマインダーのタスクをもとに、AIが取り組む内容を提案。制限中のSNSを使いたいときは、AIに理由を伝えて相談します。タスクに取り組むか、必要な利用をするかをAIと相談することで、何となくSNSを開く前に立ち止まるきっかけを作ります。

利用の流れは次のとおりです。

1. 各種アプリのアクセスを許可し、連携するリマインダーのリストと制限するアプリ、制限時間を選ぶ。

2. 自分で設定した制限時間を利用時間が越えたら、警告を出す。
3. 制限されたSNSを使いたくなったら、ToDoメでタスクを確認する。
4. タスクに取り組むか、AIに今SNSを使いたい理由を相談する。
5. 一時利用を認める場合は、アプリが条件と上限を検査して解除する。
6. 一時利用の終了後は再び制限し、タスクへ戻るきっかけを作る。

未完了タスクとアプリ別の利用時間上限を制限開始条件にどう組み合わせるか、一時利用の時間・回数・例外、再制限の方式は検討中です。

### 特長

#### 1. 特長1いつもの「いじりすぎちゃった」が「やる事の完了」につながる

いつもぱっとスマホを手に取り、SNSを開くユーザーはこのアプリがなければ、きっとSNSを何時間を見ていたことでしょう。
ですがこのアプリを導入したユーザーは、AIチューター「アリ」が、おすすめのやることに案内してくれることで、いつもの「いじりすぎちゃった」と、マイナスになってしまう時間が「やることを終わらせられた」時間へ、プラスに変わります。

#### 2. 特長2「使いたい理由」をAIに相談

「何となく見たい」と「必要な連絡を確認したい」などと、ユーザーのSNSの利用目的は様々です。タスクと会話の内容を踏まえて、次の小さな行動や必要に応じた短時間利用を提案する対話を設計しています。

#### 3. 特長3「アリとキリギリス」にちなんで、ユーザーの意識に問いかける

童話「アリとキリギリス」をモチーフとし、AIチューターを「アリ」、ユーザーを「キリギリス」にあてはめました。努力を重ねる「アリ」と、怠ける「キリギリス」のどちらになりたいかを、ユーザーに意識的に問いかけることで、ユーザーの思考をSNSを開くことよりも、やることを終わらせる方向へもっていきます。
親しみのあるキャラクターと対話することで、たのしくやることに取り掛かってもらいたいという思いも込められています。

### 解決出来ること

次の課題への支援を目指します。利用時間の削減や習慣改善の効果は、今後の検証対象です。

- 無意識にSNSを開く前に、やるべきことを思い出す。
- 大きなタスクにも、まず小さな一歩から取り組む。
- 必要なSNS利用は相談し、利用後にタスクへ戻る。

### 今後の展望

まずは、実際のリマインダー取得から、アプリ制限、AIとの対話、一時利用後の再制限までを実機でつなぎます。そのうえで、タスクへの着手状況や利用者の納得感を確かめ、対話と制限条件を改善していきます。

音声での相談による入力負担の軽減や、Androidへの展開も検討しています。

### 注力したこと（こだわり等）

-
- 設計で重視しているのは、次の2点です。

* **本人が納得して動ける対話。** 本人のタスクと事情を踏まえ、次にできる行動を短く具体的に伝えることを目指しています。
* **会話と利用制御のつながり。** AIの提案をアプリのルールで検査し、一時利用の終了後まで状態を管理する設計を検討しています。

## 開発技術

### 活用した技術

#### API・データ

- 外部API・サーバーなし（データは端末内で完結）
- アプリのデータ：JSONファイルに保存
- やること：リマインダーと連携（EventKit）
- AIとの会話：端末内AI（Apple Foundation Models）。使えない端末ではキーワードによる簡易応答に切り替え
- 本体と拡張機能の間：App Group で制限の状態を共有

#### フレームワーク・ライブラリ・モジュール

- SwiftUI / Observation
- Foundation Models（端末内AI）
- Screen Time API（FamilyControls / ManagedSettings / DeviceActivity）
- EventKit（リマインダー連携）
- Swift Charts（利用時間のグラフ）
- Swift Testing（テスト）

#### デバイス

- iPhone（iOS 26以上）

### 独自技術

#### ハッカソンで開発した独自機能・技術

- AIとの相談の設計：端末内AIには、返答・納得度・次の行動を決まった型で出させる。やることの名前や会話はデータとして扱い、会話から判定を書き換えられるのを防ぐ。AIが「許可」を出しても、アプリのルールで再検査してから制限を解く
- アプリを閉じていても効く制限：上限への到達や一時利用の終了をスクリーンタイムの拡張機能で検知し、アプリが裏にいても制限をかけ直す
- 使用時間の扱い：SNSの使用時間はスクリーンタイムの拡張機能の中だけで扱い、アプリ本体には渡さない
- SNS時間の台帳：獲得と利用を取引として記録し、同じ報酬の二重付与を防ぐ
- 端末内AIがなくても動く相談：端末内AIを使えないiPhoneでは、キーワードから納得度を出す簡易応答で相談を続ける
