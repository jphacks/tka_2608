# Instagramから始めるデモ

2026-10-18 / Personal Team用。URLの指定は不要です。ショートカットのアクションから本体を開き、既存Routerへ固定の `instagram` を渡します。[Apple: AppIntentからアプリの画面を開く](https://developer.apple.com/documentation/appintents/creating-your-first-app-intent)

## iPhone側の設定

1. Xcodeで **`todomeru_ios_PersonalDemo`** を選び、iPhoneへRunして上書きします。現在の無料Teamのままで、追加のentitlementは使いません。
2. **todomeru Demo** を通常起動して初回設定を済ませ、デモ候補のInstagramを選択します。実Instagramもインストールしておきます。
3. **ショートカット → オートメーション → ＋ → アプリ** でInstagramだけを選択し、**「開いている」「すぐに実行」**にします。旧UIでは「実行の前に尋ねる」をOFFにします。[Apple: 自動実行の設定](https://support.apple.com/ja-jp/guide/shortcuts/apd602971e63/9.0/ios/26)
4. 「次へ」が表示されていれば押し、**「新規の空のオートメーション」**を選びます。すでにアクション編集画面にいる場合は、そのまま下の操作を行います。

「Instagramのデモ制限を確認」は状態を裏側で取得する処理で、確認画面ではありません。「もし」も内部の条件分岐です。実行時にショートカットの編集画面を開く必要はありません。[Apple: 「もし」の動作](https://support.apple.com/ja-jp/guide/shortcuts/apd83dcd1b51/ios)

### 手順4の具体的な操作

1. **「アクションを検索」**で `待機` を検索し、「待機」を追加します。
2. 追加された「1秒 待機」の数字をタップし、**5秒**に変更します。＋／−が出る場合は＋で5にします。
3. アクション検索で `Instagramのデモ制限を確認` を検索し、**todomeru Demoが提供する同名のアクション**を追加します。アプリ一覧のtodomeru Demoから選んでも構いません。
4. `もし` を検索して「もし」アクションを追加します。
5. 「もし」の入力を、直前の **「Instagramのデモ制限を確認」の結果**にします。自動設定が違う場合は入力欄から「変数を選択」で直前の結果を選び、**真（はい）の場合**に実行する条件にします。これは利用者に「はい」を押させる設定ではありません。
6. `Instagramの制限画面を開く` を検索して、todomeru Demoが提供するアクションを追加します。**そのカードを長押しし、「もし」と「その他の場合」の間へドラッグ**します。「その他の場合」の中は空にします。
7. 下記の並びを確認して **「完了」**で保存します。URLや標準の「アプリを開く」アクションは追加しません。

```text
待機：5秒
Instagramのデモ制限を確認
もし［確認結果］が［はい］
    Instagramの制限画面を開く
その他の場合
    （空）
もしの終了
```

保存後はショートカットを閉じ、ホーム画面からInstagramを開いて確認します。ロック解除状態で、許可枠がないときに約5秒後にtodomeruの「やることやろうぜ」へ進む構成です。初回にOSのアクセス許可が表示された場合は事前の動作確認で許可してください。OSの一時バナーを含む実際の表示挙動は実機未検証です。

以前の設定を使っている場合は、「URL」「URLを開く」を削除し、代わりに **「Instagramの制限画面を開く」** を「もし」の内側に追加します。アクションが出ないときは、更新版を一度通常起動し、ショートカットを開き直して `todomeru Demo` またはアクション名で検索します。

## デモの動作と範囲

- ロック解除状態で実Instagramを開くと、待機後に「やることやろうぜ」へ進みます。遷移にはOSの実行時間も加わります。
- タスク・AI相談は既存のロジックを使い、許可後に「Instagramを開く」を押すと実Instagramへ戻ります。`instagram://app` が使えなければ、画面の案内どおりホーム画面から開いてください。
- 既存の利用枠がある間は確認結果が「いいえ」となり、画面を開きません。専用の経過時間による期限は撤去しました。実Instagramの利用で枠を消費しないため、時間経過だけでは再制限しません。既存の朝4時の日付切替で枠が失効し、次の判定に反映されます。ショートカットの設定変更は不要です。
- Instagramへ切り替えるたびに再判定します。連続利用中に時間切れで本体へ強制遷移する機能ではありません。[Apple: アプリの作動機能](https://support.apple.com/ja-jp/guide/shortcuts/apde31e9638b/9.0/ios/26)
- 会話・タスク選択・取り組み・ふりかえりが進行中なら、その画面を保持します。
- PersonalDemoの合計の「遊んだ時間」とInstagramの個別使用時間は固定30分。週グラフは当日30分・他の日0です。他の疑似アプリの個別表示は従来どおりです。計測・加算や、そのためのテストは追加していません。
- 連携を止めるときは該当オートメーションを無効にします。デモ候補のInstagramを選択解除しても介入しません。

ビルド・既存テストの結果と実機未検証範囲は [STATUS.md](STATUS.md) に記録します。実際のScreen Timeによる制限・使用時間取得の実証には含めません。
