### 用語の統一（ユーザー指定）

| 指すもの                                                | 本書・実装時の表示で使う用語                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------ |
| 今ユーザーがするべきこと、TODO、ToDo、タスク            | **やること**                                                       |
| 制限する対象全般。X・Instagram・YouTube・ゲーム等を含む | **SNS**。固有名はそのまま使う                                      |
| 利用を止めている状態、ブロック                          | **制限**。「制限中」「SNSを制限する」                              |
| 1日に使える時間の限度                                   | **上限**。「1日の上限」「上限に到達」                              |
| 獲得した利用時間                                        | **SNS時間**。「SNS時間に○分追加」。貯めて持ち越す表現は使わない（D034） |
| 開放・解放という表現                                    | 状態に合わせて「SNSを○分利用できます」「SNS時間に○分追加しました」 |

「制限」と「上限」を混同しない。上限は時間の設定値、制限はSNSを利用できない状態。内部の処理説明では「制限の一時解除」を使ってよいが、上限を増やしただけでSNSが利用可能になったとは表示しない。本体・OS・拡張の技術上の区別や既存の識別子は、表示用語とは別に扱う。

Figmaには旧表記が一部残る。本書の画面名と文言は上表を適用した表記であり、Figma内の文字列をそのまま引用したものではない。たとえば「つい開くSNSと、使う時間」「やることを1つ完了したら」「どのSNSに使う？」と記載する。

## 3. 文言と画面状態

### 体験の軸

やることに戻る選択と、事情を説明してSNSを使う選択を両方用意する。アリは事情を聞き、小さな行動を提案する。人格を否定したり、完了していないことを完了したと決めつけたりしない。色・キャラクターだけで状態を伝えず、短い文章と次の操作も示す。

## 4. AIとの対話・プロンプト案

### 対話の進め方

1. 最新のやることから、始められる候補を短く提示する。
2. SNSが今必要な理由を聞く。すでに説明された事情を繰り返し尋ねない。
3. やることの小さな一歩、別の確認方法、短時間のSNS利用を状況に応じて提案する。
4. 本体が条件を検査し、制限の変更やSNS時間の適用が成功してから確定文言を出す。
5. 実行後は進捗を確認し、本人の「完了にする」と元データの更新結果を区別する。
6. ホーム起点のふりかえりでは、獲得したSNS時間の追加先を選んでもらい、成功した対象を明示する。

### システム指示の叩き台

```text

説明済みの事情を何度も聞きません。

SNS内のDMだけ見られる等、本体が保証していない制御を約束しません。
```
