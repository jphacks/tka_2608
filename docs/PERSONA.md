# ペルソナとプロダクトの目的（検討用）

更新日: 2026-10-17 / 状態: **ターゲットの定義はユーザー指定（D019）。ペルソナの人物像・場面・目的の文言はAIの叩き台で、チームの合意前。**

この文書は、議事録（T01）、今回の依頼（U01）、2026-10-17のユーザー発言（D019）、Figmaの基準画面（[UI_UX.md 2節](UI_UX.md#2-figmaの基準画面と現状の遷移)）、審査基準（O02）をもとに書いています。各項目に根拠を書きました。根拠欄が「推定」の項目はAIが補ったもので、チームの記録やユーザー調査に基づくものではありません。採用したら [DECISIONS.md](DECISIONS.md) に決定者・理由とあわせて記録してください。

審査の「実行・実現可能性」では、想定ユーザが不明確だと1点、競合に対する優位性があると4〜5点です（O02）。T01の10-17メモにも「ターゲット層を明確に」とあります。ピッチの「問題点、解決方法」の説明も、この文書を起点にする想定です。

## 1. ターゲット

**本当はやらないといけないことがあるのに、ついついSNSやゲームをやってしまう人。**

ユーザーの発言（D019）: 「ターゲットは、本当はやらないといけないことがあるのについついSNSやゲームをやっちゃう人なら。だから一人暮らし社会人で家事やってないのにゲームしている人でもいい」

ターゲットは属性（学生・社会人）ではなく、**やるべきことがあるのに先延ばしして娯楽アプリを開いてしまう**という行動で定めます。

- やるべきこと: 課題・レポートに限らず、家事などの生活のタスクも含む。
- 逃げ先: SNSに限らず、ゲームも含む。
- 立場: 学生でも社会人でもよい。一人暮らしの社会人も対象。

以下のペルソナは、このターゲットに含まれる人の具体例です。ペルソナに含まれない属性の人を対象外にするものではありません。

## 2. プロダクトの目的

### 一文で言うと（案）

**SNSやゲームを開こうとしたその瞬間に、自分のリマインダーにあるタスクを踏まえてAIと短く話し、「今なにをするか」を自分で選び直せるようにする。**

「SNSやゲームを禁止する」ことではなく「開く前に一度立ち止まって選び直す」ことを目的に置いています。T01の「AIを頑張って説得しないとSNSを使えない」という方向性と、「本当に必要な時に困る」という既存アプリへの不満の両方を満たすには、この置き方がよいと考えました。

### 解きたい問題

| 問題 | 根拠 |
| --- | --- |
| 少しSNSを見るつもりが、使い続けてしまう | T01「モチベーション: ついSNSを見てしまう。」 |
| やるべきこと（課題・家事など）があるのに、SNSやゲームを先にしてしまう | D019 |
| 自制心だけでは続かない。1人でスマホを触っているときは特に難しい | T01（しのさんのメモ） |
| Screen Timeの制限は自分で解除できてしまう。親の許可方式は、連絡がつかないと困る | T01「既存の制限アプリの問題点」 |
| 一定時間開かなくなる制限アプリは、本当に必要なときに困る | T01「既存の制限アプリの問題点」 |
| 決まり文句の警告は慣れてしまい、「はいはい」と解除される | T01 10-16「UI/UX面」 |

「気づけば30分」という表現がT01にありますが、これはAIが書いたスライド文の例です。計測値として使わないでください。

### このアプリが提供する価値（案）

1. **思い出させる**: 自分で登録したリマインダーのタスクを、SNSやゲームを開く瞬間に見せる。
2. **一緒に選ぶ**: 人間相手と違って気を使わずに相談できるAIが、事情を聞いて次の小さな行動を提案する（T01「気を使わずチューターしてくれる」）。1人で暮らしていて声をかけてくれる人がいない場面でも働く。
3. **必要なら通す**: 必要な連絡などは、アプリのポリシーが認める範囲で一時的に使える。AIの返答だけでは解除しない（[AGENTS.md](../AGENTS.md)）。

### 目的にしないこと

- SNSやゲームの時間をゼロにすること。必要な利用まで止めると、「本当に必要な時に困る」という問題を再生産する。
- 解除不能にすること。個人向けのScreen Time認可は本人が取り消せるので、そう訴求しない。
- 威圧や羞恥でやめさせること。議事録の「詰められる」はアイデアの表現であり、要件ではない（[AI_CONTEXT.md 5節](AI_CONTEXT.md#5-uiuxの設計方針案)）。
- ToDoアプリを作り直すこと。タスク管理は標準リマインダーに任せる（T01 10-15）。
- 効果を主張すること。「SNS時間が減った」「家事をするようになった」は計測するまで書かない。

## 3. ペルソナ案

どちらも架空の人物です。

### ペルソナA: 課題から逃げてSNSを開く学生

Figmaのタスク例（レポート）とそのまま対応するので、デモで最も見せやすいペルソナです。チーム自身と属性が近く、Hack Day中に自分たちで使って確かめられます。

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| 呼び名 | ユイ（架空） | — |
| 立場 | 理工系の大学2〜3年生。授業の課題・レポートが毎週ある | 推定。チームの学年構成とFigmaのタスク例から |
| 端末 | iPhone（Apple Intelligence対応機種）。標準リマインダーに課題の締切を入れている | U01（iPhone・既存リマインダー）。対応機種はT01 10-16のメモ |
| 逃げ先 | X、Instagram | Figmaの「Xを開く」、T01「インスタ開けるように」 |
| 抱えているタスク | 「レポート 序論2段落目の続き」のような、途中で止まった課題 | Figmaのタスク選択72:2 |
| 困っていること | 手が止まると無意識にSNSを開き、戻れない。Screen Timeを設定しても自分で解除してしまう | T01の問題点を人物に当てはめた |
| 本音 | やめたいわけではない。グループ課題の連絡などでSNSが必要なときもある | T01「本当に必要な時に困る」、AI_CONTEXT.mdの会話例 |
| 欲しいもの | 責められずに、次に何をすればいいかを一言で示してくれる相手 | T01「気を使わず」「お前が言うなら我慢するか」 |

**典型的な場面:** 平日の夜。ユイはレポートの序論を書いているが、2段落目で手が止まった。気づくとXのアイコンをタップしている。

- **今まで**: Screen Timeの制限画面が出るが、「制限を無視」を押して開く。30分ほど見て、罪悪感だけが残る。
- **このアプリがある場合**: 制限画面からアリとの対話に進む。アリは「序論の2段落目が残っているね。まず1文だけ書いてみない？」と提案する。ユイは書き出しのアイデアがないと話し、アリは見出しの一言から始めることを提案する。ユイはタスクに戻ることを選び、取り組み中の画面に移る。

この流れはFigmaの「ブロック27:203 → 説得チャット30:2 → タスク選択72:2 → 取り組み中37:2」に対応します。会話文は検討用の例であり、採用したプロンプトではありません。

**サブシナリオ（本当に必要な連絡）:** 同じユイが、グループ課題の集合場所を確認するためにSNSを開きたい場合です。AIは事情を確認し、ポリシーが許す範囲で一時的な利用を提案します。時間が来たら再び制限をかけます。「何となく見たい」と「必要な連絡」で返答が変わることは、既存の制限アプリとの違いを示す要素で、デモの見せ場になると考えます。解除の時間・回数・条件は未決定です（[STATUS.md](STATUS.md) Q05）。

### ペルソナB: 家事を後回しにしてゲームをする一人暮らしの社会人

D019でユーザーが例に挙げた人物像です。ターゲットが学生に限らないことを示します。

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| 呼び名 | ソウ（架空） | — |
| 立場 | 一人暮らしの社会人。平日は仕事で、家事は帰宅後と週末にまとめてやるつもりでいる | D019。働き方の詳細は推定 |
| 端末 | iPhone（Apple Intelligence対応機種）。標準リマインダーに「洗濯」「ゴミ出し」「食器洗い」などを入れている | U01。家事の内容は推定 |
| 逃げ先 | スマホゲーム、SNS | D019 |
| 抱えているタスク | 洗濯物を干す、明日の朝のゴミ出しの準備など、短いが期限が近い家事 | 推定 |
| 困っていること | 帰宅してソファでゲームを始めると止まらず、家事が翌日に回る。一人暮らしなので誰にも注意されない | D019を人物に当てはめた |
| 本音 | ゲームは息抜きとして続けたい。家事が片付いていれば罪悪感なく遊べる | 推定 |
| 欲しいもの | 「先にこれだけやれば遊べる」と区切りを示してくれる相手 | 推定。T01「できたら褒める＋短い時間解除もあり」に近い |

**典型的な場面:** 平日の21時に帰宅。洗濯機は回したが、干していない。ソウはソファに座ってゲームアプリを開こうとする。

- **今まで**: そのままゲームを始め、気づくと日付が変わっている。洗濯物は洗濯機の中に残ったまま。
- **このアプリがある場合**: 制限画面からアリとの対話に進む。アリは「洗濯物がまだ干してないみたい。5分で終わらせてから遊ぶのはどう？」と提案する。ソウは干し終えたことをリマインダーで完了にし、アプリに戻る。

会話文は検討用の例であり、採用したプロンプトではありません。タスク完了で遊べる時間が増える（T01「ToDo一つ消化したらSNS1分時間制限追加」）かどうかは未決定です。

ペルソナAと違う点が3つあり、設計に影響します（4節）。

- タスクが短く、体を動かす作業で、スマホから離れて行う。
- 「毎日」「毎週」の繰り返しタスクが多い。
- 完了したかどうかをアプリから確かめられない。

### デモで見せる2つのルート

デモでは「タスクをやった」ルートと「AIを説得した」ルートの**両方**を見せます（D020、ユーザー指定）。Figmaのブロック画面27:203にある2つのボタン「タスクを先に片付ける」「AIを説得する」に対応します。

| ルート | 流れ（Figma） | 伝えること |
| --- | --- | --- |
| ① タスクをやった | ブロック27:203 →「タスクを先に片付ける」→ タスク選択72:2 → 取り組み中37:2 → 完了ふりかえり90:2 | やるべきことに戻れる。終えたら褒められる |
| ② 説得した | ブロック27:203 →「AIを説得する」→ 説得チャット30:2 → ポリシーの検査 → 一時利用 → 時間切れ32:309・再制限 | 事情があれば、AIとの対話を経てルールの範囲で使える。時間が来たら戻る |

2つのルートを並べると、「やるべきことに戻す」と「必要なときは使わせる」という、既存の制限アプリにない両立を示せます。

以下は提案で、未合意です。

- **人物の割り当て**: ①と②の両方をペルソナAで見せると、Figmaの画面とタスク例をそのまま使える。①をペルソナBの家事（5分で終わる洗濯物干し）にすると、ターゲットが学生に限らないことも同時に示せる。
- **②の理由**: 「グループ課題の集合場所を確認したい」のような必要な連絡にすると、説得が通る理由が審査員にも伝わりやすい。
- **②の流れの補足**: Figmaでは「Xを開く」から時間切れ画面へ直接つながっている（[UI_UX.md](UI_UX.md) U01）。デモでは、ポリシーによる解除と再制限が実際に動くかどうかを区別して示す。
- **説得失敗32:2**: 時間に余裕があれば、何となく見たいだけの相談では説得が通らない例も見せられる。必須にはしない。

一時利用の時間・回数・条件は未決定です（[STATUS.md](STATUS.md) Q05）。完了ふりかえり後に報酬（利用時間の追加など）を出すかどうかも決まっていません。

## 4. 対象外・後回しにする人

| 対象 | 理由 |
| --- | --- |
| 保護者が子どもの利用を管理したい家庭 | 本人が自分のために使うアプリとして設計している。保護者による管理はScreen Timeの認可方式も異なる |
| SNSやゲームが仕事で必須な人（SNS運用担当など） | 制限の前提が成り立たない |
| 依存症の治療が必要な人 | 医療的な支援の代わりとして訴求しない |
| Apple Intelligence非対応のiPhone、Androidの利用者 | Hack Day中の対象外。Androidは将来方針（D003）。非対応端末への説明UIは必要 |

## 5. ペルソナから導く設計上の要求

| ペルソナの事情 | 設計への反映 | 関連 |
| --- | --- | --- |
| タスクはすでにリマインダーにある | 新規入力を求めず、既存タスクを読む | AI_CONTEXT 6節 P0「タスク取得」 |
| 逃げ先はSNSに限らずゲームもある | 制限対象は本人が選ぶ。SNS専用の文言にしない（例:「Xを開く」を対象アプリ名に差し替えられるようにする） | D019、UI_UX U05 |
| 手が止まった瞬間に開いてしまう | 制限画面から対話までの手数を少なくする | UI_UX U01・Q07 |
| 責められると反発して解除する | 短く、理由と次の小さな行動を示す。質問は原則1つにする | UI_UX 3節「体験の軸」 |
| 必要な連絡もある | 事情に応じた一時利用と、確実な再制限 | P002、Q05・Q06 |
| 決まり文句には慣れる | 実在のタスク名・期限を使い、毎回同じ文にしない | T01 10-16 |
| 家事は短く、スマホから離れて行う（B） | 「5分で終わる」など所要時間の小ささを示す提案ができるようにする。取り組み中画面を見続ける前提にしない | 推定 |
| 繰り返しタスクが多い（B） | 繰り返し設定のあるリマインダーを正しく扱えるか確認する | 推定。EventKitでの扱いは未検証 |
| 完了をアプリが確かめられない | 完了は自己申告として扱い、AIの判断だけでリマインダーを書き換えない | AI_CONTEXT 5節 |
| タイピングが面倒なときもある | 音声入力は候補。P0の実機経路を優先する | AI_CONTEXT 6節 P2 |

ゲームアプリをSNSと同じようにScreen Timeで制限できるか（アプリ単位・カテゴリ単位の選択）は、実機では確認していません。

## 6. ピッチでの説明の骨子（案）

1. **問題**: やるべきことがあるのに、「ちょっとだけ」のSNSやゲームが止まらない。既存の制限は、自分で外せるか、必要なときまで止めてしまう。
2. **誰の問題か**: 課題を抱えた学生も、家事を後回しにする一人暮らしの社会人も。私たち自身もそうです。
3. **解決**: SNSやゲームを開く瞬間に、自分のタスクを知っているAIと話して選び直せる。必要な連絡なら、ルールの範囲で通す。
4. **デモ**: Xを開く → 制限画面 → ①タスクを選んで取り組み、完了する／②AIを説得して一時利用し、時間が来たら再制限。両方を見せる（D020）。
5. **AIエージェントらしさ**: 状況（タスク・事情）を取得し、提案し、ポリシーの検査を経て実行し、結果を確認する（[AI_CONTEXT.md 9節](AI_CONTEXT.md#9-受賞のために示したいこと)）。

実機で確認できていない部分は、デモで「モック」と明示します。
