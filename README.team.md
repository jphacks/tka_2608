## 作るもの

**ついSNSを開いてしまう瞬間に、やるべきことを思い出させ、一緒に行動を選び直してくれるAIチューター。**

iPhoneの既存リマインダーと連携し、未完了タスクがあるときにSNSなどの選択したアプリを制限します。利用したいときはAIと対話し、タスクへの着手や必要に応じた一時解除を相談します。「このAIが言うなら、いったんやってみるか」と思えるUI/UXを重視します。将来はAndroidにも広げたい、という方針です。

これは目標の説明です。この文書作成時点ではリポジトリにアプリ実装はありません。

## まず知っておくこと

- 開発は4人という依頼です。議事録には5名の自己紹介があり、当日の参加者・担当は未確認です。
- 主な受賞目標は、東京Aが対象に含まれるULSのAIエージェント賞とAward Dayへの進出です。賞の条件は貼付公式資料に基づきます。
- Swift、Foundation Models、EventKit、Screen Time APIが議事録の技術候補です。SwiftUI、保存方式、最低OS、実機・署名環境はこれから決めます。
- 「SNSの上に自由なAIチャットを重ねる」は技術確定事項ではありません。iOS標準の制限画面と、本体アプリの対話画面をつなぐ方法を先に検証します。

## 1日目午後の進め方

午前にFigmaをもとにイメージが固まったという共有を受け、午後は4人を技術班とUI・対話班に分け、検討結果を今日中のデモ実装に渡します。2人ずつを出発点とする案ですが、人数・個人の担当は未割当です。技術班は [ARCHITECTURE.mdの8節](docs/ARCHITECTURE.md#8-午後の検討実装引き継ぎ)、UI・対話班は [UI_UX.md](docs/UI_UX.md) を使ってください。進行と担当は [STATUS.md](docs/STATUS.md)、採用した判断は [DECISIONS.md](docs/DECISIONS.md) に残します。

## 実装・実機検証で取り組むこと（提案）

1. Mac/Xcode、デモ用iPhone、OS、Apple Developerの署名・権限、端末でのモデル利用可否を確認する。
2. 1つのアプリを選び、実際に制限して本体の対話へ移れるか検証する。
3. 実リマインダー取得 → タスクを踏まえた対話 → 方針に沿った解除判断、の一本道をつなぐ。
4. 一時解除の期限・利用時間の意味を決め、バックグラウンドで再制限できるか確認する。
5. 実装と並行して、動作デモ、提出情報、技術的な工夫が分かる差分・記録を用意する。

音声入力はユーザー指定で今回のスコープ外です。対話には文字入力を使います。タスク自動生成、学習アプリ利用での報酬、Android実装は追加候補であり、必須スコープとして合意したわけではありません。
